## Three different sizes

Our texture is **256 × 64 pixels**. It contains four **64 × 64 pixel** cells in a
single row. The sprite is still **160 × 160 world units**. A texture rectangle
selects source pixels; it does not choose the displayed size.

| Frame | `IntRect(left, top, width, height)` |
| ----- | ----------------------------------- |
| 0     | `(0, 0, 64, 64)`                    |
| 1     | `(64, 0, 64, 64)`                   |
| 2     | `(128, 0, 64, 64)`                  |
| 3     | `(192, 0, 64, 64)`                  |

Always supply an explicit rectangle when first assigning the texture. Then use
`setTextureRect()` to change frames without loading a new file or recreating a GPU
texture. Keep every cell within the texture dimensions; this sample uses uniform
cells without atlas rotation, trimming or packing metadata.

## Advance by time

At eight frames per second, one frame lasts `1 / 8 = 0.125` seconds. The full
four-frame cycle takes `0.5` seconds. Accumulate `deltaTime` and wrap at the cycle
length. Advancing once per rendered frame would make animation speed depend on the
display frame rate. In Engine, the current `update()` step is fixed by the configured
update rate; accumulating that step still measures simulation time.

<Code code={clock} lang="cpp" title="AtlasAnimation.hpp" />

The remainder preserves partial frame time and handles a step spanning several
frames or cycles. Reducing a long step before adding avoids an unbounded catch-up
loop. Zero, negative and non-finite time values do not advance the animation.

Only movement and the selected source rectangle change during `update()`. Normal
drawing comes from `FirstSprite`. While minimized, this example's boundary movement
stops but its animation clock continues; on restore it displays the current frame.
This is an explicit sample policy, not an automatic Engine pause.

`destroy()` releases the atlas while the window context is still alive. It also
calls the inherited cleanup, which safely handles the unused empty PNG texture.
Never release the atlas after destroying the GL context or copy its ownership
through a `Sprite`: sprites only borrow textures.

## Build and verify

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DRB2D_BUILD_CORE_EXAMPLES=ON
cmake --build build --config Release --target robot2D-sprite-animation robot2D-core-lessons-test
ctest --test-dir build -C Release -R '^core-lesson\.animation$' --output-on-failure
```

Run `build/examples/sprite-animation/Release/robot2D-sprite-animation` (add `.exe`
on Windows). No asset path or special working directory is needed. Move with
WASD/arrows, observe the light loop and exit with Escape.

Headless tests check frame order, wraparound, a long update, invalid time, equivalent
split updates, rectangle dimensions and differing atlas pixels. They do not prove
GPU sampling or visible playback. If the beacon stretches, check `setSize()`; if it
shows the whole strip, check the 64 × 64 source rectangle.
