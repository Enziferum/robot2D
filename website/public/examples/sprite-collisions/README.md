# Core lesson 06 — simple sprite collisions

Targets `0.8.0-dev` from bde7d42, including Window metrics baseline 79369b2.
Build inside a configured robot2D checkout with the lesson 01/02 directories available:

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_POLICY_VERSION_MINIMUM=3.5 -DRB2D_BUILD_CORE_EXAMPLES=ON
cmake --build build --config Release --target robot2D-sprite-collisions robot2D-sprite-collisions-test -j 4
ctest --test-dir build -C Release -R '^core-lesson\.collision-' --output-on-failure
```

Run `build/examples/sprite-collisions/Release/robot2D-sprite-collisions` (`.exe` on
Windows), from that directory. CMake copies the shared `assets/robot.png` there;
an optional first argument overrides its path. Preserve your build toolchain and
native dependencies; MinGW requires matching runtime DLLs on PATH.

WASD/arrows move. Escape exits. The complete player quad has a dark backing that
turns amber while movement is blocked. Walls are fixed in an 800x600 world; resize
changes the visible area without moving them. Positive size, normalized origin,
zero rotation, default scale and non-overlapping starts are required. This is an
X-then-Y kinematic axis sweep, not Box2D, pixel masks or general continuous physics.
The solver allows sliding and prevents crossing thin static walls along each axis;
it does not repair an overlapping spawn or model a straight diagonal sweep.

Optional hidden-window GL check (requires a working display/GL driver):

```sh
cmake -S . -B build -DRB2D_CORE_EXAMPLE_GRAPHICS_TESTS=ON
cmake --build build --config Release --target robot2D-sprite-collisions-graphics-test
ctest --test-dir build -C Release -R '^core-lesson\.collision-render$' --output-on-failure
```

The graphics check exercises the published setup/update/render, contact/wall pixels,
nine quads and repeated cleanup; exit 77 means unavailable GL, not a pass.
Five headless scenarios cover bounds, directions, sliding, sweeps and application input.
Manual acceptance: all four wall faces, diagonal sliding, leaving a contact, corner
stability, focus loss, resize and visible colors. No UI automation is used.

Source is under the included Zlib license. The Robot Lab PNG retains the asset
notice in lesson 01; the one-pixel wall texture is generated by this example.
