# robot2D website

Astro + Starlight, a static English-language website in SlateTeal. Task [WEB-02 / #133](https://github.com/Enziferum/robot2D/issues/133). This directory is independent of the native editor build.

## Local development

Use Node.js 24+ and pnpm 11.25.0 (the package manager is pinned in package.json). From this directory:

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Open the localhost address printed by Astro. The server binds to 127.0.0.1. For production-output inspection:

```sh
pnpm check
pnpm format:check
pnpm build
pnpm verify
pnpm preview
```

No C++ build, account, token or browser automation is required. Pagefind search is generated by the production build; use `pnpm preview` to check the final search experience.

## Hosting configuration

GitHub Pages is the selected host: `https://enziferum.github.io/robot2D/`. The Website workflow publishes after website-related pushes to `dev`, or manually from a selected branch. Ordinary pull requests only run checks. See [Pages setup and manual publication](deploy/github-pages.md), including the first pre-merge deployment from WEB-02.

Production origin/base path come from `actions/configure-pages`, so a later custom domain is supported. The default local path is `/`. Set `SITE_URL` for canonical URLs, social images and the sitemap; without it, local builds skip the sitemap rather than inventing a domain.

Set `SITE_BASE` when hosting below a path, for example `/robot2D/`. Use the same environment for build, verification and preview:

```powershell
$env:SITE_URL = 'https://YOUR-REAL-HOST'
$env:SITE_BASE = '/robot2D/'
pnpm build
pnpm verify
pnpm preview
```

Website navigation and media URLs use `src/lib/site.ts`; Starlight handles its own base path. The PR workflow checks both `/` and `/robot2D/`. Its `example.invalid` origin is only a test fixture, never a production configuration.

## Source of truth

- Engine development version: read from the parent CMakeLists.txt during Astro configuration. Do not raise the engine version to change the website.
- Public release history starts at **0.8.0**. `src/data/releases.json` is a dated snapshot; `scripts/release-policy.mjs` filters it both during sync and rendering. An empty public catalogue is valid. The original pre-0.8 snapshot is preserved only in `../docs/archive/github-releases-before-0.8.0.json`, outside the site output. Normal builds and visitors make no GitHub API request.
- Refresh releases explicitly with `pnpm sync:releases`, review the diff, then commit. Optional `GITHUB_TOKEN` is read only from the environment. Errors preserve the existing snapshot. Drafts, invalid tags and versions below 0.8.0 are excluded; prereleases are labelled, and binary buttons come only from actual attached assets. Downloads prose must also be reviewed when a new public distribution appears.
- Roadmap goals: parent `docs/release-roadmap.md` and GitHub milestones. No dates or completion claims are inferred.
- Documentation: introductory Starlight guides live in `src/content/docs/docs/`; the extra directory puts documentation at `/docs/` while marketing pages use `src/pages/`.

## Media and design

`public/media/robot-lab-editor.png` is the developer-supplied screenshot, preserved byte for byte. Its SHA-256, captured build and art provenance are recorded in `public/media/provenance.json`. The WebP is a compressed derivative for delivery; the full PNG is available by clicking the screenshot.

The image shows ASSET-01 development UI, including SlateTeal, toolbar and AssetsPanel work, not the historical v0.7 release. It contains generated game artwork inside a real running editor. No generated UI mockups are presented as product screenshots.

Shared palette tokens are in `src/styles/tokens.css`, with separate marketing and Starlight styles. Widget SlateTeal colours come from ASSET-01 EditorStyles.cpp; website copy uses brighter accent and muted colours for contrast. The active Robot Lab 02 raster mark and 03 mascot are documented in `../logo/robotlab-slateteal/`. Earlier SVG candidates are archived; the site uses the selected transparent PNG mark with live text. The first version uses a fixed dark theme and system fonts; there are no external font services.

## Checks and remaining acceptance

`pnpm verify` parses the built HTML, checks required routes, local links, anchors, images, scripts and the Pagefind bundle. It catches broken subdirectory paths as well as missing files. It does not test external links or execute browser interactions.

The layout includes responsive breakpoints, a skip link, visible keyboard focus, image alternatives and reduced-motion support. Visual, keyboard and search interaction acceptance is manual: inspect the home and docs pages at desktop and narrow mobile widths, follow main navigation, open the original screenshot, use docs search, and verify the 404 page. No computer-use is permitted for this project; user acceptance remains necessary.

Next: complete GitHub Pages publication and manual acceptance, publish more small Core articles and reproducible Robot Lab lessons, then package a demo and a short real gameplay recording. A custom domain can be connected later. Donations are omitted until a real destination is agreed.

## Screenshot proportions

`EditorShot` keeps the source image dimensions for layout but uses CSS `width: 100%; height: auto` so the rendered image retains its aspect ratio. Showcase has a wider image container (up to 1600 px). Manual acceptance: check the editor screenshot at desktop and mobile widths; square controls and the robot should retain their proportions, with no cropping or horizontal overflow.

## Selected Robot Lab branding

The user selected logo **02** as the primary mark and character **03** as the site mascot.
Active assets are in `public/brand/robot2d-logo-02-*` and `robot2d-mascot-03-*`;
masters and exact generation prompts are in `../logo/robotlab-slateteal/`.
The provenance manifest records original master hashes. These are transparent raster assets,
not vector stand-ins. Header, footer, Starlight and favicon use 02. The home page uses 03,
with WebP and PNG fallback, explicit dimensions and lazy loading. Old v1 candidates remain archived.
Editor integration is a separate worktree/PR, BRAND-01/#135, using the same selected source.
Manual acceptance: logo at 100/150/200% scaling, mascot against the site background,
responsive page layout and screenshot aspect ratio. No browser automation is used.
