# Robot Lab — GAME-01, этап 1

Одноэкранный платформер на текущем публичном C# API robot2D. Это исходный
проект: четыре твёрдые платформы, фиксированная камера 1280×720, движение,
один прыжок и возврат после падения. Игровой маршрут: START → 02 → 03 → EXIT.
EXIT пока обозначает конец маршрута; победа, ячейки, checkpoint, лазеры,
анимации и пауза относятся к следующим этапам.

## Открыть и поиграть

Нужна сборка robot2D с SCRIPT-01/PHYS-01 (база этого шага — dev 4132acf),
Mono/mcs и Python для сборки скриптов. Все пути к ресурсам относительные.
Скомпилированные DLL и копия ScriptCore не входят в исходники.

Текущий ProjectSerializer хранит Path буквально, поэтому сначала подготовь
отдельную рабочую копию (PowerShell 7):

```powershell
./Prepare-Demo.ps1
```

Она появится в `work/RobotLabPlatformer` рядом с этим README. Можно задать
`-Destination 'C:/My Games/RobotLabPlatformer'`; имя конечной папки должно
совпадать с именем проекта. Существующий каталог не перезаписывается.
Скрипт копирует assets/настройки скриптов и задаёт локальный Path только в копии;
отслеживаемый исходный проект не меняется.

1. Запусти редактор и выбери Add existing → подготовленную папку.
2. Открой `Platformer.scene`, нажми Play, открой Game и дай ему фокус.
3. Редактор сам собирает `assets/scripts/PlayerController.cs` против своей
   свежей ScriptCore при открытии/Play. Ошибки находятся в Console.
4. A/D или стрелки — движение; Space/W/Up — прыжок по новому нажатию; R —
   возврат на старт. Удержание прыжка не даёт автопрыжков.
5. Первый прыжок делай ближе к правому краю стартовой платформы, затем пройди
   ещё две платформы до EXIT. При падении робот возвращается автоматически.

Между запусками редактируй подготовленную копию или исходник осознанно:
это разные папки. Для чистого переноса запусти Prepare-Demo в новый каталог.

## Как работает текущий API C#

Потребитель API целиком находится в [PlayerController.cs](assets/scripts/PlayerController.cs).
Типизированные оболочки компонентов не содержат копию физического состояния:
свойства обращаются в native engine через internal calls.

```csharp
public override void OnCreate()
{
    body = GetComponent<RigidBody2D>();
    transform = GetComponent<TransformComponent>();
    drawable = GetComponent<DrawableComponent>();
    spawn = transform.Translation;
}
```

`GetComponent<T>()` возвращает null, если компонента нет. В полном исходнике
есть проверка обязательных компонентов. `OnCreate` вызывается для нового
runtime-экземпляра, поэтому spawn относится к данному запуску Play.

```csharp
Vector2 velocity = body.LinearVelocity;
body.LinearVelocity = new Vector2(axis * MoveSpeed, velocity.Y);
```

`Transform.Translation` измеряется в пикселях, `LinearVelocity` — в физических
единицах, сейчас 32 пикселя на метр. Y направлена вниз: прыжок задаёт
отрицательную Y-скорость. Горизонтальная скорость задаётся напрямую, вертикальная
сохраняется: гравитация и столкновения остаются ответственностью Box2D.

Ввод пока polling: `Input.IsKeyDown(KeyCode.Space)`. Для одного прыжка контроллер
сам хранит предыдущее состояние кнопки. Это не новый action API и не готовое
распределение коротких нажатий по fixed ticks. Текущий callback — `OnUpdate(float dt)`;
планируемый `OnFixedUpdate` пока отсутствует, его здесь не имитируем.

```csharp
public override void OnCollisionEnter2D(
    ulong other, ref PhysicsContact2D contact, Vector2 normalToMe)
```

Также есть Stay и Exit. `normalToMe` уже направлена к получателю: Y < -0.5
означает опору снизу. Стена и потолок прыжок не разрешают. Набор опор по ID
сохраняет заземление при нескольких контактах; Exit убирает только свою опору.
Trigger callbacks не участвуют в определении земли. При взлёте опоры очищаются,
а отрицательная Y-скорость запрещает второй прыжок по остаточному контакту.

Для возврата используется `body.Type = RigidBody2D.BodyType.Kinematic` и скорость
в сторону сохранённого spawn, затем нулевая скорость и Dynamic. Это видимый
быстрый возврат, не teleport API. Запись Translation динамическому телу меняет
Transform, но не переносит Box2D; поэтому так возвращать игрока нельзя.
Текущий native setter отдельно умеет перемещать кинематическое тело, однако
демо не зависит от этой специальной ветки. Современный контракт respawn/teleport
можно будет выбрать вместе с runtime API отдельно.

`DrawableComponent.Flip()` меняет направление спрайта; коллайдер в сцене
симметричен по горизонтали и не зависит от разворота.

## Проверки и ручная приёмка

Постоянные тесты входят в `robot2D-editor-test-suite` как `editor-platformer-*`.
Они компилируют именно игровой исходник против свежей ScriptCore и выполняют
его под Mono с настоящими scene serializer, native component calls, Box2D
и доставкой C# столкновений. Только физическая клавиатура заменена заданными
состояниями. Это не временный smoke-тест и не замена контроллера C++ логикой.

```text
cmake --build <build-dir> --target robot2D robot2D-editor-test-suite -j 4
ctest --test-dir <build-dir> -R editor-platformer --output-on-failure
```

Ручной сценарий: пройти до EXIT; удержать прыжок при посадке; попробовать
прыжок в воздухе; упасть слева и справа; повторить падение несколько раз;
нажать R на платформе и в полёте; удерживать прыжок во время возврата;
Stop → Play и проверить исходную позицию. Попробовать длительный низкий FPS.
Ощущение управления и полный путь через UI принимает пользователь.

Пауза, focus/capture, 0/N fixed ticks, coyote time/буфер и анимации остаются
во втором этапе GAME-01. Готовая standalone-поставка проверяется после
интеграции PLAYER-01/BUILD-01; этот пример её не объявляет готовой.
