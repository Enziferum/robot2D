Правила выдачи ID, GitHub Issues/Projects и обязательный префикс коммитов —
в [правилах работы](project-workflow.md). Реестр существующих ID — `.github/tasks.json`.

## LOAD-01: первоначальный анализ и текущий прогресс

**Исполнители:** очередь и интеграция — ассистент; CancellationToken — пользователь.
После первоначального анализа реализованы исходы задач, защита публикации сцены,
поколение запроса и исправление штатного setup/shutdown. Ошибка первой загрузки
показана отдельным состоянием; возврат в браузер проектов ещё не реализован.

Исходные проблемы, обнаруженные чтением кода 2026-10-15 и исправленные в ASYNC-01:

- `SceneLoadTask::execute()` при ошибке десериализации или отсутствии script interactor только пишет лог и возвращается. `TaskQueue` затем доставляет обычный callback, а `SceneManager` без проверки назначает сцену активной.
- `EditorLogic::loadSceneCallback()` очищает выделение, команды и clipboard и переводит редактор в Edit, не получая результата загрузки с ошибкой.
- `Application::destroy()` вызывает Shutdown Mono раньше `EditorModule::destroy()`, через который останавливается TaskQueue. Загрузка может ещё обращаться к scripting interactor.
- В `TaskQueue` выполнение задачи происходит под входным mutex, исключения не перехватываются, `hasPendingTasks()` всегда возвращает false; деструктор не будит condition variable перед join, а `clear()` с уменьшающимся size может оставить часть очереди.

Предложение для согласования:

1. Явный результат загрузки: успех со сценой либо ошибка с причиной; активная сцена заменяется только при успехе, UI выходит из Load в обоих случаях.
2. Для смены сцены ошибка сохраняет старую сцену; для неудачного первого открытия проекта нужен отдельный путь возврата в браузер проектов.
3. У запроса есть идентификатор или поколение, чтобы устаревшее завершение не применялось после нового запроса или закрытия проекта.
4. Завершение: запрет новых запросов и применения callback, остановка и ожидание фоновой работы, освобождение результатов задач при живых зависимостях, затем Shutdown Mono. Детальный контракт очереди согласовать с пользователем.

Предлагаемый первый шаг реализации — передача результата ошибки по цепочке SceneLoadTask → SceneManager → EditorLogic и сохранение текущей сцены при неудачной смене. Полная переработка TaskQueue в этот шаг не входит.

Проверки после реализации: отсутствующий или повреждённый файл, недоступный interactor,
успешная смена, повторный запрос, закрытие во время загрузки и закрытие без задач.
