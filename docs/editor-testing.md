# Тесты редактора

Постоянные тесты находятся в `editor/tests/` и запускаются через CTest из корня
build-каталога. Исходники редактора компилируются общей object-целью
`robot2D-editor-objects`; редактор и тесты используют одни и те же объекты.
Тесты не включают cpp-файлы из work, не используют private/public-макросы,
не требуют пользовательских проектов или установленного тестового фреймворка.

## Обычный запуск без графики

Для уже подготовленного каталога с зависимостями движка:

```text
cmake -S . -B <build-dir> -DRB2D_BUILD_EDITOR_TESTS=ON -DRB2D_EDITOR_GRAPHICS_TESTS=OFF
cmake --build <build-dir> --target robot2D-editor-test-suite robot2D --config Debug -j 4
ctest --test-dir <build-dir> -C Debug -L headless --no-tests=error --output-on-failure
```

Генератор, компилятор и CMAKE_BUILD_TYPE выбираются при первом создании каталога,
как при сборке редактора. Для одноконфигурационных генераторов Release нужно
конфигурировать с `-DCMAKE_BUILD_TYPE=Release`, а не только передавать --config.
Зависимости CMake/Mono/GLFW/spdlog/yaml-cpp остаются теми же, что нужны редактору.
На Windows CTest добавляет каталог компилятора и Mono из конфигурации в PATH.

Headless означает отсутствие создаваемого окна и графического контекста;
тестовые executable всё ещё связаны с библиотеками редактора. Полностью отдельная
сборка модели без зависимостей графики относится к будущему разделению архитектуры.

## Интеграционные тесты сцен

```text
cmake -S . -B <build-dir> -DRB2D_BUILD_EDITOR_TESTS=ON -DRB2D_EDITOR_GRAPHICS_TESTS=ON
cmake --build <build-dir> --target robot2D-editor-test-suite --config Debug -j 4
ctest --test-dir <build-dir> -C Debug -L graphics --no-tests=error --output-on-failure
```

Нужны GLFW, доступный графический сеанс и OpenGL 4.5. Каждый процесс создаёт
скрытое окно 32×32, освобождает сцены до уничтожения контекста и не запускает
пользовательскую C#-сборку. Без доступного контекста возвращается код 77:
CTest показывает **Skipped**, что не является подтверждением прохождения сценария.
В CI Windows запускает headless-сценарии, Linux — также graphics через Xvfb/Mesa.

## Покрытие

Диагностика OpenGL и ошибки shader дополнительно проверяются двумя сценариями
`core-graphics-diagnostics` и `core-graphics-shaders` в той же suite.
Им нужен OpenGL 4.3 debug context; подробности —
[диагностика рендера](render-diagnostics.md).
Ещё 14 сценариев `core-batch-*` проверяют пиксели и статистику batching
для путей OpenGL 4.3/4.5; покрытие и ограничения —
[корректность batching](render-batching.md).

| Область | Наблюдаемое поведение |
|---|---|
| TaskQueue, 6 сценариев | Успех/ошибка/отмена, исключения worker и callback, очистка, остановка и освобождение результатов, ожидание активного callback |
| SelectionService | Порядок и уникальность выделения, активный элемент, toggle, очистка, передача собственного вектора |
| Console, 2 сценария | Дописывание, частичная UTF-8 строка, CRLF, уровни, очистка без удаления файла, замена/пересоздание файла, ограничение памяти |
| YAML и payload | Повторный Save, сохранение исходного файла при ошибке, NUL в пути, занятые временные имена, drag/drop → OpenSceneMessage |
| INI, 2 сценария | Камера, видимость панелей и layout после повторного чтения; значения по умолчанию при повреждённых полях |
| Кэш проектов | Повторное чтение, нормализация путей, удаление только записи, восстановление с backup, миграция старого формата, сохранение будущего формата без перезаписи |
| Версия редактора | Одинаковая версия в конфигурации, окне, новом проекте и кэше; чтение старого проекта с Editor Version 0.5, независимость CacheVersion |
| Ошибка записи кэша, Windows | Реальный sharing violation: не меняются ни память, ни исходный файл |
| Иерархия сцен | Parent/child, порядок корней, запрет циклов, чужих сущностей и повторного UUID |
| Сериализация | Иерархия и компоненты после перестановки YAML-записей, повреждённые документы, старый формат и prefab |
| Save/dirty | Dirty сбрасывается после успешного Save/Save As; ошибка не меняет путь и данные; NaN не повреждает старый файл |
| Диагностика отказа Save | Отсутствующая сцена / script interactor: путь и причина в журнале, SceneSerialize, файл/dirty/path сохранены; повторный успех сбрасывает ошибку |
| Async load | Применяется последний запрос; ошибка файла или отсутствие scripting interactor сохраняют активную сцену |
| Закрытие проекта | Ошибка Save не подтверждает закрытие, успешный Save и Discard выполняют соответствующее действие |
| Первое открытие | Ошибка переводит Load в LoadFailed и не публикует сцену |

CHECK и require бросают исключение и работают при NDEBUG. Каждый сценарий — отдельный
процесс с собственной рабочей папкой в `<build-dir>/editor/tests/scenarios/`.
Файловые проверки создают уникальный fixture внутри этой папки; при ошибке данные
сохраняются для разбора. Логи находятся в папке сценария, отчёты CTest — в
`<build-dir>/Testing/Temporary/LastTest.log`. Параллельный запуск сценариев допустим.

## Добавление сценария

Добавить проверку публичного поведения в EditorTests.cpp или SceneTests.cpp
и зарегистрировать имя в editor/tests/CMakeLists.txt. Проверки работы с Scene
относятся к graphics-группе до отделения модели от графических зависимостей.
Сбой подготовки данных/записи fixture — ошибка теста, а не повод пропускать проверку.
Не применять assert к действиям с побочными эффектами: в Release они исчезнут.

## Ручные проверки UI

Автоматические проверки модели и маршрутизации не заменяют проверку настоящего окна:

- Повторный drag/drop сцены → Save, повторное открытие и сохранность данных.
- Save / Discard / Cancel через реальные popup: Cancel оставляет сцену и выделение.
- Ошибка записи: popup остаётся открыт, ошибка видна, проект не закрывается.
- Автооткрытие последнего проекта после запуска; закрытие во время загрузки и runtime.
- Иерархия, Inspector, viewport/gizmo и восстановление layout визуально.

Набор тестов не закрывает остальные этапы roadmap и не проверяет ещё не реализованный
CancellationToken. Проверка его interrupt points добавляется вместе с реализацией.

## Результат TEST-01, 2026-10-15

На Windows / MinGW GCC 15.2 / Debug прошли 27 сценариев: 18 headless
(параллельно, -j 4) и 9 graphics без пропусков. Цель robot2D также собрана после
изменения структуры CMake. В существующий CI добавлены сборка и обязательный
headless-запуск для Windows/Linux; удалённый CI и Linux локально не запускались.
Затем при настройке CI-01 выполнен отдельный прогон Ninja/Release:
редактор собран, 17 зарегистрированных core-тестов и 18 headless-сценариев прошли.
Настройка CI и просмотр отчётов описаны в [CI и отчётах](ci.md).


## Оконные scopes ImGui

`imgui-scope-windows`, `imgui-scope-unwind`, `imgui-scope-panels` и
`imgui-scope-docking` входят в robot2D-editor-test-suite и headless-группу.
Создают настоящий ImGui context/кадр без native окна и GL: видимость callback,
стек окон/стилей после раннего выхода/исключения, вложенность, состояние/focus
IPanel и сохранение docking при скрытом host. Запуск: `ctest --test-dir <build-dir>
-R imgui-scope --output-on-failure`. Крестик зарегистрированной панели,
перезапуск с layout и внешний вид проверяются вручную по IMGUI-01.
