# Анимация 0.8: клип, preview и C#

Шаг ANIM-01 от 2026-10-16, ветка `codex/anim-01-clip-playback` от dev 64dab8f.
Включён проверенный commit 80dbe5c из [SCRIPT-01 PR #113](https://github.com/Enziferum/robot2D/pull/113):
он обеспечивает свежий ScriptCore и managed-тесты. При интеграции сначала слить
SCRIPT-01; изменения ресурсов [ASSET-02 PR #111](https://github.com/Enziferum/robot2D/pull/111)
остаются отдельным предшественником. Этот шаг не закрывает всю ANIM-01.

## Контракт

- Клип содержит упорядоченные кадры с индексами от 0, положительный целый FPS,
  имя и флаг loop. Каждый `.anim` хранит один клип; несколько именованных файлов
  привязываются к сущности существующим списком Animations в сцене.
- `playAnimation` выбирает клип по имени для UUID сущности, показывает первый кадр
  и запускает Animator. Повторный Play уже активного клипа не сбрасывает время.
  После завершения/Stop следующий Play начинает клип заново. При смене клипа
  первый кадр устанавливается сразу. Неизвестное или неоднозначное имя, пустой
  клип, неверный FPS и отсутствующие компоненты дают отказ, сохраняя текущее состояние.
- Loop сохраняет остаток времени при пропуске нескольких циклов. Однократный клип
  останавливается на последнем кадре. Отрицательный/нечисловой dt игнорируется;
  большие конечные dt обрабатываются без переполнения индекса.
- Stop без имени останавливает текущий клип. Stop с другим именем не прерывает его.
  Состояние воспроизведения хранится в AnimatorComponent, отдельно от определения клипа.
- Две системы анимации реализуют существующий cloneSelf для Play-сцены. Transient
  playback из editor preview не наследуется при клонировании; дальнейшее время
  runtime не меняет Animator исходной сущности. Core ECS и Snapshot не изменены.
- Определения клипов в CPU/GPU managers хранятся в deque: добавление следующего
  клипа не инвалидирует указатели на предыдущие. Многопоточность и общая очистка
  ресурсов не переделывались.

## XML

Сохраняется существующая структура `sprites/animation/cut`: image, title, delay
(FPS), x/y/w/h. Добавлены необязательные атрибуты `loop` и `flipped`; старые файлы
без них читаются как false. Версия приложения/схемы не повышается.

Загрузка проверяет обязательные поля, FPS, флаги и прямоугольники (включая границы
int), не смешивает несколько animation-элементов и заменяет выходной объект только
после полной проверки. Повторная загрузка не накапливает кадры. Порядок XML cut
сохраняется. Невалидный клип не записывается поверх существующего файла.

## C# API

В `editor/scripting` сохранены `Animator.Play(string)` и `Stop(string)`, добавлены
`TryPlay(string)`, `IsPlaying`, `Stop()`. Через Mono они вызывают общий C++ путь
preview/runtime. C# не содержит второго механизма кадров.

```csharp
Animator animator = entity.GetComponent<Animator>();
if (animator != null)
{
    bool selected = animator.TryPlay("Move");
    bool active = animator.IsPlaying;
    animator.Stop();
    animator.Play("Death"); // Для однократного Death отключить loop в файле клипа.
}
```

TryPlay возвращает false при null/пустом имени, отсутствующем компоненте/клипе,
устаревшем native entity или отсутствии scripting service. Вызов не использует
assert для этих ошибок. Новый Animator без привязанной Entity безопасен.

## Панель

Add New получает имя из stem выбранного будущего файла (раньше helper требовал,
чтобы файл уже существовал), добавляет Animation/Animator только один раз и
отклоняет повторное имя. FPS и Loop редактируются явно; Play/Stop не меняют loop.
Доступны первый/предыдущий/следующий/последний кадр и выбор через курсор. Move left,
Move right и Delete frame изменяют реальный список кадров, после чего сохраняется
новый порядок, а не только положение UI-маркера.

Slice загружает лист существующим cutter; Slice Grid с Cell width/height заменяет
список равномерной сеткой в порядке строк. Размеры положительные и делят лист
нацело; максимум 65536 кадров защищает от случайной огромной нарезки. Confirm
обновляет preview; Save пишет валидный `.anim`. Frame glue больше не использует
итератор на удалённый элемент. Повторная нарезка не дописывает старые кадры.

При смене выделения preview останавливается, указатели/выбранные кадры сбрасываются,
асинхронный результат старого выбора игнорируется. Редактирование панели во время
Play отключено и смена выделения в этот момент не останавливает игровую анимацию.
AnimationSystem не обращается к отсутствующей текстуре и не делит UV на нулевой размер.

## Проверки и оставшаяся приёмка

Постоянные headless-сценарии `editor-animation-*`: grid/index/reorder/delete/glue,
FPS/loop/one-shot/large dt, именованные клипы/стабильные адреса/неоднозначность,
XML roundtrip/legacy/повреждённые данные, настоящий C# → Mono → native и runtime clone.
Тест runtime-clone сначала воспроизвёл отсутствие AnimatorSystem, затем прошёл
после добавления cloneSelf. Настройка и запуск — [editor-testing.md](editor-testing.md).

Ручной сценарий (в этом шаге ещё не выполнен):

1. Создать для Drawable сущности Idle/Move/Attack/Death в отдельных `.anim` внутри
   assets, нарезать регулярный лист, удалить/переставить кадры и сохранить сцену.
2. Закрыть и открыть проект; проверить имена, порядок, FPS и loop. Курсором и
   кнопками просмотреть первый/последний кадр, Play/Stop не должны менять loop.
3. Во время нарезки сменить сущность, очистить выделение, выбрать сущность без
   Animation. Старый callback не должен менять новый выбор или приводить к падению.
4. В C# переключать клипы каждый Update, проверить отсутствие постоянного restart;
   Death проигрывается один раз и остаётся на последнем кадре. Неизвестное имя
   возвращает false, не прерывая активный клип.
5. Войти в Play во время editor preview; runtime начинает свой playback. Выделять
   разные сущности, Stop/Play повторить, убедиться в неизменности сохранённых данных.
6. После готовности PLAYER-01/BUILD-01 повторить тот же сценарий в собранной игре.

Standalone, реальная UI/игровая приёмка и полная независимость повторных Play/Stop
в рамках RUNTIME-02 этим headless-шагом не объявляются проверенными. State machine,
blending и сложный timeline не входят в этот объём.

Локальный результат этого шага: Windows/Mono 6.12, Ninja/Release; собраны robot2D,
robot2D-core-tests и robot2D-editor-test-suite; полный CTest 84/84 без пропусков,
включая 38 graphics и шесть новых headless-сценариев анимации. Предварительный
строгий clang-tidy семи ключевых изменённых единиц прошёл. Полный обязательный
hook выполняется перед публикацией коммита; итог записывается в PR/Issue.
