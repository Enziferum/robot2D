# Минимальный HUD из C#

Шаг HUD-01 от 2026-10-16: ветка HUD-01 от dev df823bb, отдельный worktree.
Ведущий — ассистент по поручению пользователя. Пример игры и его баланс остаются
в C#, ECS/fixed tick и полный restart сцены относятся к своим задачам.

## Настройка сцены

1. Создать три сущности Health, Wave, Status. Для каждой добавить Drawable и Text.
   В Text выбрать импортированный шрифт из assets/fonts; сохранить сцену.
2. Разместить надписи в видимой области камеры, например (16,16), (16,48), (16,80).
   Для минимальной арены камера неподвижна. Это текст в координатах сцены:
   screen-space anchors и самостоятельная HUD-камера этим шагом не добавляются.
3. У фона/игровых объектов задать меньший Drawable depth, у надписей больший,
   например 0 и 10, и использовать один render layer. Больший depth рисуется позже.
   Цвет надписи берётся из Drawable. Геометрия glyph задана в пикселях шрифта;
   положение/поворот/scale берутся из Transform, Size прямоугольника не умножает glyph.
4. Скопировать [HudExample.cs](examples/HudExample.cs) в C# каталог проекта,
   собрать, назначить HudExample сущности-контроллеру. В Inspector назначить
   HealthLabel, WaveLabel и StatusLabel соответствующим TextComponent сцены.
5. Запустить Play. Ожидаются Health: 100, Wave: 1 и пустой Status. Игровой код
   вызывает SetHealth/SetWave при изменениях; при нуле здоровья появится Game Over.
   В примере R по фронту нажатия вызывает RestartRound и сбрасывает только данные
   примера/надписи. Настоящий сброс врагов, физики, таймеров и мира — RUNTIME-01;
   RestartRound не является API перезагрузки сцены.

## API и границы

```csharp
label.Text = "Health: " + health;
label.Text = null;                  // очистить
bool applied = label.TrySetText("Wave: 2");
string current = label.Text;
```

Text хранится и передаётся через Mono как UTF-8. Detached/недоступная сущность,
отсутствующий TextComponent или отключённый scripting service дают false из
TrySetText; getter возвращает пустую строку. Property setter использует ту же
проверку, но не сообщает результат. Встроенный NUL отклоняется без изменения текста.
Это не добавляет компоненты автоматически и не вызывает native assert на stale
ссылке. Для значимой игровой проверки используйте TrySetText.

Текущий Font atlas движка содержит ASCII. Другие code points сохраняются в строке,
но рисуются как один `?` на code point; полноценный Unicode shaping/atlas expansion
не реализован. Перевод строки поддерживается; шаг строки — CharacterSize.
Остальной размер glyph задаётся загруженным шрифтом и Transform scale.

TextSystem больше не рисует общий буфер всех надписей для каждой сущности.
У каждой сущности отдельные GPU batches, каждый не более 1000 glyph quads;
длинный текст разбивается без переполнения. Отложенный renderer получает стабильные
VAO для каждой надписи и сохраняет порядок относительно обычных quads.
Пустой/не загруженный шрифт пропускается. Смена шрифта очищает glyph cache;
текстура принадлежит shared_ptr, копия runtime-компонента сохраняет её время жизни.
Геометрия небольшого HUD обновляется каждый update, чтобы учитывать положение,
цвет и состояние текста. Оптимизация dirty cache не является целью этого шага.
Несколько независимых камер/слоёв с разной проекцией для текста требуют отдельной
проверки; минимальный сценарий использует один layer и одну камеру.

## Проверки и приёмка

Постоянный editor-hud-managed загружает свежую ScriptCore через настоящий Mono,
вызывает API из C#, проверяет Health/Wave/Game Over/reset, UTF-8 roundtrip,
null, embedded NUL, detached/отсутствующий компонент и отключённый service.
Сам HudExample.cs компилируется и исполняется этим тестом.

editor-scene-hud-text проверяет GL pixels двух надписей разными шрифтами/цветами,
фон и перекрывающий quad, очистку, 2001 glyph, недостающий шрифт и смену шрифта.
Редактор/core-tests/editor-test-suite собраны; полный CTest 105/105, включая
42 graphics. Это независимая ветка от dev: тесты SCRIPT-01 PR #125 в неё не включены.

Ручная приёмка ещё нужна: назначить поля в Inspector, Play/Stop/Play, вызвать
SetHealth(0), нажать R и убедиться в восстановлении надписей. Затем сохранить,
закрыть/открыть сцену, проверить шрифт и depth. Поставка без редактора проверяется
после PLAYER-01/BUILD-01; HUD-01 до этой приёмки остаётся открытой.
