# robot2D Core API

Документированы `robot2D/Util/ResourceHandler.hpp`, `Core/Message.hpp` и
`Core/MessageBus.hpp`, а также `Util/Logger.hpp` и `Util/Assert.hpp`.
ECS, внутренние реализации и сторонние библиотеки в этот справочник не входят.

## ResourceHandler

Контейнер единолично владеет ресурсами. Загрузка синхронная, повторный ID
отклоняется без повторной загрузки и без изменения существующего ресурса.
`get()` и `operator[]` бросают `std::out_of_range`, если ID отсутствует.
`find()` возвращает указатель либо `nullptr`, не меняя контейнер.
Вставка сохраняет выданные ссылки; они действительны до уничтожения контейнера.
Требования к потоку и графическому контексту определяет ресурс. При одновременной
модификации контейнера требуется внешняя синхронизация.

```cpp
robot2D::ResourceHandler<robot2D::Texture> textures;
if(textures.loadFromFile("player", "player.png")) {
    const auto* texture = textures.find("player");
    // Use texture while textures and the required GL context remain alive.
}
```

## Генерация

Нужен Doxygen. Для проверенного отдельного build-каталога:

```text
cmake -S . -B <build-dir> -DRB2D_BUILD_DOCS=ON
cmake --build <build-dir> --target robot2D-core-docs
```

Результат: `<build-dir>/docs/core/html/index.html`. Опция по умолчанию выключена;
обычная сборка не требует Doxygen. Генерация не добавлена в цель ALL.
Версия берётся из корневого `project(robot2D VERSION ...)`.
Некорректная разметка блокирует генерацию; полнота покрытия комментариями пока
не является обязательной для ещё не документированных модулей.

## Описания API

Описания находятся у публичных объявлений в заголовках. Они фиксируют результат,
ошибки, владение и срок жизни указателей, единицы измерения, требования к потоку
или GL-контексту. Для простых методов достаточно одной строки. `@param`,
`@return`, `@throws`, `@warning` добавляются, когда объясняют контракт.
Технические описания API сохраняют английский язык существующих заголовков;
руководства проекта написаны по-русски. Комментарии меняются вместе с поведением.

## Сообщения и память

Типизированные payload MessageBus создаются через value initialization и
уничтожаются при `clear()` или уничтожении шины. `pollMessages()` извлекает
оболочку, сохраняя payload действительным до очистки. После очистки использовать
ранее выданные Message и ссылки на payload нельзя. Необходимо выбирать `T` по
ID сообщения: проверка размера не различает разные типы одинакового размера.
Операции шины из деструктора payload не поддерживаются.

Предел шаблона (128 байт по умолчанию) относится к типизированным сообщениям.
Raw-сообщения сохраняют возможность передавать более длинные сериализованные
пути; их размер ограничен свободной памятью арены. Исчерпание арены вызывает
`BadMessageAllocation`; ошибка конструктора не оставляет сообщение в очереди.
Арена занимает 1 MiB; типы с выравниванием более 128 байт не поддерживаются.
Редактор освобождает batch после синхронной доставки всей очереди.

## Logger

`logger::Log::Init()` создаёт Core/Editor/Client каналы и общий журнал
`robot2D.log` в текущем рабочем каталоге. До первого логирования можно явно
выбрать путь через `Init("logs/session.log")`; родительский каталог должен
существовать. Все getters, включая `getFilePath()`, безопасно вызывают Init
с defaults, если явного запуска ещё не было.

Первая успешная инициализация начинает сессию с очисткой выбранного файла.
Последующие вызовы сохраняют тот же путь, логгеры и содержимое файла;
переданный им путь игнорируется. Это предотвращает потерю журнала при
повторном вызове инициализации движка. Имя канала, занятое чужим logger,
считается ошибкой до открытия файла и не заменяется.

Исключения открытия/регистрации или разрешения пути передаются вызывающему коду.
Неуспех не публикует частично готовые каналы; Init можно повторить с исправленным
путём. Инициализация сериализуется mutex, готовность публикуется атомарно только
после завершения. В проверенном MinGW окружении вариант с исключением внутри
std::call_once зависал при повторной попытке; тесты отказа/повтора проверяют
выбранный вариант с mutex.

Работа готовых `_mt` sinks допускает одновременное логирование. Как и прежде,
каждое сообщение немедленно сбрасывается в файл: это сохраняет поведение
ConsolePanel и диагностику перед сбоем. Уровни и формат даты/потока сохранены.
Мутируемые getter-слоты оставлены для совместимости capture-тестов; заменять
их можно только без одновременного использования. Нельзя сбрасывать слоты
в nullptr, удалять registry entries каналов или вызывать spdlog::shutdown
при последующем использовании этих каналов. Повторный Init не создаёт новую сессию.

Форматтеры vec2u поддерживают `{}`/`{:d}`, vec2f — `{}`/`{:f}`/`{:e}`.
Дробные значения сохраняются, вывод float использует один знак после точки.
Другие спецификаторы отклоняются через fmt::format_error.

## Assertions

Основной заголовок — `robot2D/Util/Assert.hpp`. Старый `Core/Assert.hpp` включает
его для совместимости. Заголовки самодостаточны, предварительно включать Logger
не нужно. Каждый вызов заканчивается точкой с запятой:

```cpp
RB_CORE_ASSERT(resource != nullptr);
RB_ASSERT(width > 0, "Invalid width {} for resource {}", width, id);
```

По умолчанию assertions включены без NDEBUG (обычный Debug), отключены с NDEBUG
(обычный Release). Presence-макрос RB_ASSERTS явно включает их и в Release;
его значение 0 не отключает проверки. Старый генерируемый RB_DEBUG здесь не
используется, чтобы поведение зависело от конфигурации компиляции конкретной цели.

При включённой проверке условие вычисляется один раз. Аргументы сообщения
вычисляются и форматируются только при ошибке; поддерживаются до 14 значений
форматирования. Неуспех пишет выражение, файл, строку и сообщение в stderr
и выбранный канал (Client или Core), затем вызывает std::abort. Если журнал
недоступен или форматирование завершилось ошибкой, процесс всё равно завершается
с диагностикой в stderr. RB_DEBUGBREAK также вызывает std::abort во всех сборках.
Интерактивная остановка/продолжение через платформенный debugger trap не вводилась.

Отключённые assertions не вычисляют ни условие, ни аргументы сообщения. Поэтому
в них нельзя помещать обязательные для работы побочные эффекты; ошибки внешних
данных и обычные отказы следует обрабатывать через API, а не assertion.

Тесты: отдельные процессы Logger; форматтеры в core-tests; GTest death tests
assertions с RB_ASSERTS, без NDEBUG (Debug default) и с NDEBUG (Release).
Сборка robot2D-core-tests включает все эти цели; запуск — обычным CTest.

## FileInputStream

`robot2D/Core/FileInputStream.hpp` — владеющий синхронный поток двоичного чтения.
Путь передаётся в UTF-8; Windows использует wide-path открытие, POSIX — байты
пути. Пустой путь и встроенный NUL отклоняются. Любой `openFromFile` закрывает
прежний файл; успешное открытие начинает чтение с нуля, неуспешное оставляет
поток закрытым. Повтор после ошибки разрешён. Копирование/перемещение запрещено;
деструктор закрывает файл. Для совместного доступа нужна внешняя синхронизация.

Все размеры и позиции — байты. Возвращаемый тип uint64_t сохранён, но вместо
неявного `-1` используется именованное `FileInputStream::Error` (UINT64_MAX).
`read` возвращает число прочитанных байтов: короткое чтение допустимо, ноль
означает EOF при ненулевом запросе, Error — отказ. При ошибке ввода-вывода буфер
может быть частично заполнен, а курсор сдвинут: такой результат нужно отбросить.
Нулевой запрос на открытом потоке возвращает ноль и допускает nullptr; ненулевой
запрос требует буфер нужного размера. nullptr, размер сверх size_t и операции
закрытого потока возвращают Error. Сам размер доступной памяти проверяет вызывающий.

`seek` принимает абсолютное смещение, проверяет его представимость до приведения
и допускает позицию за EOF без расширения файла. Используются _fseeki64/_ftelli64
на Windows, fseeko/ftello и off_t на POSIX (на поддерживаемых desktop — 64 бита).
Успешный seek сбрасывает EOF/ошибку чтения. `tell` работает и в позиции EOF.
`getSize` проверяет переход в конец и восстанавливает исходную позицию, включая
позицию за EOF. Если восстановление не удалось, возвращает Error, позиция
не определена; EOF/error indicators могут быть сброшены. Внешнее изменение
файла не синхронизируется. Отказы открытия возвращают false; нехватка памяти
при обработке пути может передаваться исключением.

```cpp
robot2D::FileInputStream input;
if(input.openFromFile("assets/data.bin")) {
    char bytes[256];
    const auto count = input.read(bytes, sizeof(bytes));
    if(count == robot2D::FileInputStream::Error) {
        // Handle the read failure; discard this buffer.
    }
    else if(count == 0) {
        // End of file.
    }
    else {
        // Process exactly count bytes, not necessarily sizeof(bytes).
    }
}
```

Регрессии: binary/short read/EOF, пустой файл, getSize с сохранением позиции,
ошибочные аргументы, reopen и повтор после отказа, UTF-8 каталоги/имена,
позиционирование и разреженный файл больше 4 GiB. Windows отдельно проверяет
некорректный UTF-8 и ошибку чтения заблокированного файла с последующим повтором;
POSIX проверяет ferror при чтении каталога. Реальные аппаратные отказы диска
и принудительный отказ восстановления позиции автоматически не моделируются.

## Time и Clock

`Time` хранит знаковое целое число микросекунд, а не секунды или календарную
метку. `Time()` равен нулю, `Time(1500000)` — 1,5 секунды; отрицательные значения
разрешены. `asMicroSeconds()` возвращает точное исходное int64_t, включая крайние
значения. `asSeconds()` и `asMilliSeconds()` сохраняют float API: делят в double
и лишь затем округляют в float. Это устраняет прежнее раннее округление, например
для ровно 16008 секунд и 134219 миллисекунд. Float всё равно не хранит каждую
микросекунду на больших интервалах; для точного значения используйте microseconds.
Имена методов с существующей капитализацией и неявный конструктор сохранены.

`Clock` измеряет прошедшее время через std::chrono::steady_clock. Коррекция
системных даты/часов не меняет направление хода. Это elapsed time, не CPU time
и не время суток; учёт сна всей системы зависит от реализации steady_clock ОС.
Точность результата — целые микросекунды с отбрасыванием меньших долей; нулевой
интервал допустим, разрешение источника может быть грубее микросекунды.

- Оба начала отсчёта устанавливаются одним now при создании.
- `duration()` возвращает время с создания без изменения состояния.
- `restart()` возвращает время с предыдущего restart, первый — с создания;
  затем обновляет только начало очередного интервала и увеличивает счётчик.
- `getRestartsCount()` возвращает число restart; unsigned size_t переполняется
  по модулю своего диапазона. Duration не увеличивает счётчик.

Копирование/перемещение сохраняют точки отсчёта и счётчик; далее экземпляры
независимы, новая копия не начинает время с нуля. Совместный доступ с restart
или присваиванием требует внешней синхронизации. Интервалы должны помещаться
в native duration steady_clock и int64_t микросекунд; арифметика сверх диапазона
не поддерживается. Изменение private clock type требует пересборки потребителей;
совместимость уже собранных бинарных клиентов не обещается. Engine по-прежнему
получает float delta через restart().asSeconds(), менять его цикл не требуется.

```cpp
robot2D::Clock clock;
const auto frameDelta = clock.restart().asSeconds();
const auto lifetimeUs = clock.duration().asMicroSeconds();
const robot2D::Time interval(1500000); // 1.5 seconds, constructor takes microseconds
```

Постоянные Time/Clock тесты проверяют единицы/знак/крайние значения, регрессии
прежнего округления, монотонность, границы первого/повторного интервала, сохранение
общего времени и независимость копии. Временные проверки ограничивают результат
реальными внешними steady_clock наблюдениями, не требуют точного времени sleep
и допускают нулевой быстрый интервал. Изменение системных часов/сон ОС тестами
не выполняется; гарантию монотонности задаёт выбранный стандартный источник.


Time поддерживает C++17 constant evaluation: конструктор определён в заголовке,
конструкторы/присваивания копии и перемещения и три getter объявлены constexpr
и noexcept. Деструктор остаётся тривиальным defaulted, без constexpr (C++17).
Time.cpp больше не нужен и удалён из CMake. Обычные вызовы с runtime-данными
сохраняются. Static assertions проверяют значения, преобразования, крайние
microseconds, копирование/перемещение и noexcept-гарантии. Clock этим дополнением
не меняется.

```cpp
constexpr robot2D::Time interval(1250000);
static_assert(interval.asSeconds() == 1.25F);
static_assert(noexcept(interval.asSeconds()));
```

## Vector2 и Vector3

Согласованный совместимый шаг: существующая арифметика остаётся constexpr,
Vector2::dot/cross и сравнения Vector3 также стали constexpr. as<U>() и asVec2<U>()
доступны у const-объекта и не меняют исходник. Vector3 из Vector2 получает z=0,
asVec2 отбрасывает z. Преобразования сохраняют правила static_cast: дробная часть
при допустимом float-to-int преобразовании отбрасывается, диапазон проверяет
вызывающий код. Скалярные операторы требуют прежний тип T; новые перегрузки
умножения/смешанных типов и новые математические операции не добавлены.

Для встроенных арифметических T конструкторы, операции и сравнения имеют noexcept.
Для преобразований это требует арифметических T и U. Для прочих типов спецификация
консервативная: арифметика/преобразования могут бросать, даже если конкретный scalar
сам не бросает. Шаблон не ограничивается арифметическими типами. Copy/move гарантии
следуют соответствующим is_nothrow traits скаляра; прежний безусловный noexcept
move исправлен, чтобы исключение пользовательского T не вызывало terminate.
Noexcept не проверяет деление на ноль, переполнение signed integer или недопустимый
диапазон преобразования: действуют обычные правила арифметики C++.

Vector2::dot/cross возвращают прежний float; сами произведения/суммы выполняются
по правилам выражений с T до преобразования результата. Поэтому unsigned arithmetic
сохраняет wraparound, integer overflow не исправляется переходом в float.
Vector2 < и > требуют строгого сравнения обеих компонент. Например (1,5) и (2,4)
не меньше и не больше друг друга. Это не лексикографический порядок и не comparator
для упорядоченных контейнеров. Изменение типов dot/cross или смысла сравнений
остаётся отдельным обсуждением.

```cpp
constexpr robot2D::vec2i direction(1, 2);
static_assert(direction.as<float>() == robot2D::vec2f(1.F, 2.F));
static_assert(direction.dot(robot2D::vec2i(3, 4)) == 11.F);
static_assert(noexcept(direction + direction));
```

Static assertions проверяют конструирование, const-преобразования, арифметику и
compound operations, copy/move, сравнения и noexcept для int/unsigned/float.
Runtime-тесты проверяют результаты арифметики/преобразований, возврат ссылки
compound operations, z в равенстве и передачу исключений пользовательского scalar.
Прежние четыре Vector2 теста с арифметическими именами, проверявшие только
равенство, заменены проверками соответствующих результатов.
