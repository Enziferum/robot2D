# Ресурсы проекта для 0.8

Первый шаг [ASSET-02 #73](https://github.com/Enziferum/robot2D/issues/73),
2026-10-15. Это контракт текущих файловых операций; интеграция полноценного
Build и проверка standalone ещё не завершены.

## Ссылки и импорт

Сериализованные ссылки имеют вид `assets/textures/player.png`,
`assets/fonts/hud.ttf`, `assets/animations/idle.anim`: они относительны
корню проекта, с `/` в качестве разделителя. Рабочий каталог процесса
не участвует в их разрешении. Форматы SceneVersion/PrefabVersion не менялись.
Абсолютный путь внутри текущего проекта при Save преобразуется в относительный;
внешний путь отклоняется с ошибкой сериализации. Старый абсолютный путь к уже
перенесённому проекту автоматически восстановить нельзя: ресурс нужно назначить заново.

`projectAssetReference` проверяет принадлежность проектному `assets`,
`resolveProjectAsset` возвращает путь для загрузчика. Пропавший файл сохраняет
свою ссылку, чтобы Save не терял возможность восстановить ресурс позднее.
Символические ссылки наружу проекта не становятся переносимыми ссылками.

В Assets Panel перейти в нужную папку и перетащить файл из файлового менеджера.
`importProjectAsset` копирует файл в текущую папку без перезаписи одноимённых
файлов. Повторное добавление уже находящегося там же файла ничего не меняет.
Ошибка содержит исходный и конечный пути и причину. Для назначения ресурса
перетащить его из Assets на Texture/Font в Inspector.

Сцена и prefab сохраняют ссылку шрифта из компонента, включая незагруженный
шрифт. Для клипа путь файла и ссылка на спрайтшит вычисляются от корня проекта,
без поиска подстроки `assets` в абсолютном пути. Ошибка записи клипа отменяет
сохранение сцены/prefab с диагностикой; уже записанные другие клипы при этом
не откатываются. Транзакционное сохранение нескольких файлов здесь не вводилось.

При отсутствии изображения/шрифта загрузчик пишет предупреждение с путём.
Подключение пустого изображения или атласа шрифта к компоненту пропускается;
отсутствующий клип не публикуется как загруженная анимация.

## Идентичность ресурсов в памяти

Продолжение ASSET-02 от `dev` @ `9f131c5`, ветка
`codex/asset-02-resource-identity`. Первый шаг уже включён через PR #105.

Ключ изображения/шрифта/текстуры в CPU/GPU-кэше — `resourceFileKey`:
нормализованный абсолютный путь с разрешёнными существующими частями пути.
Поэтому `assets/a/player.png`, `assets/b/player.png` и файл с таким же
относительным именем в другом проекте не подменяют друг друга. Этот ключ
не записывается в сцену или клип: сериализация сохраняет `assets/...`.
Одинаковый нормализованный путь повторно использует загруженный ресурс.

SceneLoadTask, EditorLogic, Inspector и путь нарезки/preview спрайтшита используют
одинаковый способ получения ключа. Неудачная CPU-загрузка не публикует пустой
ресурс, поэтому после восстановления файла загрузку можно повторить.
Callback Inspector проверяет, что компонент всё ещё ссылается на выбранный файл,
прежде чем подключать результат. Это не вводит общий hot reload/инвалидацию.

При завершении приложения после остановки очереди и освобождения EditorModule
вызывается `LocalResourceManager::releaseGraphicsResources`, пока существует
OpenGL-контекст. В graphics suite используется тот же порядок. Для этого в
Core Util добавлен `ResourceHandler::clear`; существующие операции и ECS API
не меняются. Кэш не очищается при каждом переключении проекта.

## Передача в Build

`copyProjectAssets(projectPath, destinationRoot)` копирует весь `assets` с
сохранением дерева: текстуры, шрифты, клипы, prefab и остальные проектные файлы.
Это консервативный способ не потерять зависимости в первом Build; вычисление
минимального набора использованных ресурсов не входит в этот шаг.

Получатель должен использовать свежий каталог поставки: существующий
`destinationRoot/assets` не перезаписывается. Вложенный в исходный assets
каталог назначения отклоняется. При ошибке копирования вызывающий Build должен
отбросить незавершённый результат; метод сообщает исключение, но не удаляет файлы.
Ссылки и специальные файлы внутри дерева отклоняются до копирования.

Вызов метода из ExportTask пока не добавлен: ExportTask остаётся заглушкой,
полный маршрут поставки относится к PLAYER-01/BUILD-01.

## Проверки и оставшаяся приёмка

Постоянные сценарии suite: `editor-asset-paths`, `editor-asset-import`,
`editor-asset-package`, `editor-scene-asset-roundtrip`, `editor-scene-missing-assets`,
`editor-scene-asset-identity`, `editor-scene-animation-resources`.
Они проверяют перенос каталога, Windows-разделители, родительский каталог со
строкой assets в имени, пропавшие файлы, запрет перезаписи, копирование зависимостей,
сохранение ссылок без загруженного шрифта и применение сцены без отсутствующих ресурсов.
Два новых graphics-сценария загружают настоящие изображения и шрифты из двух
каталогов/проектов с одинаковыми именами и UUID, проверяют повторное открытие,
общую текстуру для одинаковых путей, повторную нарезку и восстановление после
неудачной загрузки. Проверяется отсутствие GL errors, в том числе после явного
освобождения текстур. Изображения fixture имеют формат TGA; UI-импорт PNG/JPEG
проверяется отдельно вручную.

Ручной сценарий: импортировать PNG и TTF в Assets, назначить их сущностям,
Save → закрыть проект → перенести всю папку → открыть → проверить изображение
и текст. Удалить TTF, открыть повторно: предупреждение содержит путь, редактор
сохраняет ссылку и не падает. Вернуть TTF и перезапустить редактор для повторной
загрузки. Hot reload, общее переименование/перемещение, удаление и политика
инвалидации кэшей остаются в ASSET-01.

Остаются ANIM-01 (корректные клипы и preview/C#, включая владение списками клипов
при повторной загрузке UUID), интеграция с Build/standalone и фактическая UI-приёмка.
Этот шаг сам по себе не закрывает ASSET-02.
