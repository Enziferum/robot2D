# Анализ и форматирование C++

## Форматирование

Выбранный стиль: 4 пробела, отступ внутри namespace, открывающая скобка на той же
строке, `T*`/`T&` у типа, `if(...)` и `object -> method()`, сохранение include.

Конфигурация `uncrustify.cfg` проверена с Uncrustify 0.83.0. Локальная копия
собрана из официального тега в `work/format-tools/build/uncrustify.exe`;
этот executable не хранится в Git. Для другого checkout нужен Uncrustify 0.83.0.

Пример предпросмотра из корня проекта в PowerShell:

```powershell
& .\work\format-tools\build\uncrustify.exe -c uncrustify.cfg -f editor/src/SelectionService.cpp -o work/SelectionService.formatted.cpp
git diff --no-index -- editor/src/SelectionService.cpp work/SelectionService.formatted.cpp
```

`git diff --no-index` возвращает 1, когда есть различия. После просмотра можно
применять форматирование к конкретному файлу командой
`uncrustify -c uncrustify.cfg --replace --no-backup editor/src/SelectionService.cpp`
(без `-f`/`-o`); форматирование всего дерева отдельно согласовываем. Зависимости
в extlibs, сгенерированные файлы и содержимое build/work не включаем.

`sp_member=ignore` сохраняет уже написанные пробелы вокруг `.` и `->`; он не
добавляет их к каждому новому `object->method()`. Новый код пишем с пробелами
вокруг `->`. Это осознанное ограничение выбранной конфигурации, без текстовых
подстановок, способных затронуть строки, комментарии или trailing return type.
clang-format 21 из установленного CLion убирает эти пробелы, поэтому конфигурация
`.clang-format` в проект не добавлена. Автоформатирование CLion этим инструментом
следует отключить, если оно включено; настройки пользовательской IDE не менялись.

## clang-tidy

Корневая `.clang-tidy` включает начальный набор проверок ошибок и анализатора
Clang. Имена, длина функций и массовая модернизация пока не проверяются.
При ручном запуске предупреждения не превращены в ошибки; `-WarningsAsErrors`
делает их блокирующими. Hook использует этот строгий режим. Автоисправлений нет.
По умолчанию выбираем только `core/include`, `core/src`, `core/tests`,
`core/sandbox`, `editor/include`, `editor/src`, `editor/tests`. В корневой конфигурации заголовки
extlibs/ext исключены из выдачи замечаний. Скрипт дополнительно ограничивает
список единиц компиляции и заголовки точными абсолютными путями выбранной области.
`-Scope` заменяет стандартную область, а не добавляется к ней.

Анализ использует `compile_commands.json`. В текущем `cmake-build-debug` включён
`CMAKE_EXPORT_COMPILE_COMMANDS=ON` с сохранением компилятора, генератора и остальных
опций. Для другого подготовленного build-каталога включить ту же опцию:

```text
cmake -S . -B <build-dir> -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

Для PowerShell есть `scripts/run_clang_tidy.ps1`. Укажи путь к установленному
clang-tidy либо сделай его доступным в PATH. Скрипт получает MinGW target и
неявные include-пути от компилятора из CMakeCache, а не привязывает их к версии GCC.

```powershell
.\scripts\run_clang_tidy.ps1 -BuildDirectory cmake-build-debug -ClangTidy 'C:\Program Files\JetBrains\CLion 2025.1.1\bin\clang\win\x64\bin\clang-tidy.exe' -Files editor/src/SelectionService.cpp
```

Сначала посмотреть список без запуска анализатора:

```powershell
.\scripts\run_clang_tidy.ps1 -ListOnly
.\scripts\run_clang_tidy.ps1 -Scope editor/extlibs/robot2D-imgui -ListOnly
```

Проверить конкретную библиотеку или только один её файл (при clang-tidy в PATH):

```powershell
.\scripts\run_clang_tidy.ps1 -Scope editor/extlibs/robot2D-imgui
.\scripts\run_clang_tidy.ps1 -Scope editor/extlibs/robot2D-imgui -Files editor/extlibs/robot2D-imgui/src/robot2D/DragDropTarget.cpp
```

Можно сузить `-Scope` до подкаталога или конкретного файла. Файлы должны иметь
запись в compile database; заголовки проверяются через включающие их `.cpp`.
Если `-Files` отсутствует, берутся все единицы компиляции выбранной области,
которые присутствуют в базе. Отключённые в данной сборке тесты в этот список не попадут.
Попытка передать файл из extlibs без явного выбора его области отклоняется.
Автоисправления не включены, файлы анализатор не переписывает.

Это ограничение запуска через наш скрипт. При прямом запуске clang-tidy или
из IDE явно выбранный основной `.cpp` проверяется независимо от HeaderFilterRegex.
Подключённые заголовки зависимостей всё равно разбираются: ошибки компиляции в них
могут остановить анализ, даже если обычные замечания из этих заголовков скрыты.

Проверено 2026-10-15: `--verify-config` проходит; SelectionService анализируется
через compile database и скрипт без диагностик. Однако на main.cpp и Logger.cpp
Clang 21 из CLion с GCC 15.2 выдаёт ошибки разбора GCC intrinsic-заголовков.
Это ограничение текущего standalone-окружения, а не результат проверки этих файлов.
Для полного запуска нужен совместимый комплект Clang с его resource headers и
MinGW. Не подавлять ошибки парсера и не считать такой запуск успешным анализом.
Эта запись относится к первоначальному Clang 21; для TOOL-01 пользователь
обновил окружение до clang-tidy 23.1.3, GCC 16.2.0 и CMake 4.4.4.

## Обязательный pre-commit

Установка из корня checkout (Python 3.8+, PowerShell 7 `pwsh`, CMake, Ninja,
CTest, компилятор и зависимости редактора должны быть доступны):

```powershell
python scripts/install_git_hooks.py --uncrustify 'C:/path/to/uncrustify.exe' --clang-tidy 'C:/msys64/mingw64/bin/clang-tidy.exe' --jobs 4
```

Если инструменты есть в PATH, их пути можно опустить. Нужен Uncrustify 0.83.0.
Пути сохраняются в локальном Git config `robot2d.hooks.uncrustify` и
`robot2d.hooks.clangTidy`; число потоков — `robot2d.hooks.jobs` (по умолчанию 2).
Эти настройки общие для Git worktrees. Каталог сборки по умолчанию
`work/pre-commit-build` отдельный в каждом checkout; `--build-dir` позволяет
выбрать другой **выделенный** каталог Ninja/Release. Не указывать рабочую сборку CLion.

Для staged изменений собственного C++ hook последовательно выполняет:

1. Регрессии Python из `scripts/tests`.
2. Uncrustify `--check` для изменённых исходников и заголовков целиком.
3. Конфигурацию Ninja/Release, сборку редактора, core-tests и editor-test-suite.
4. Все зарегистрированные headless-тесты CTest (graphics отключены).
5. clang-tidy с `-WarningsAsErrors` для изменённых `.cpp` и единиц компиляции,
   включающих изменённые заголовки, по базе зависимостей Ninja.

Изменение CMake, `.clang-tidy`, `uncrustify.cfg` или скрипта запуска анализатора
вызывает полную сборку, тесты и строгий анализ всей стандартной области.
Удаление исходника тоже проверяет сборку и тесты. Заголовок или исходник без
покрытия compile database/dependency database блокирует commit: нужно подключить
его к соответствующей цели/тесту. Ошибка инструмента, анализа, форматирования,
сборки или тестов блокирует commit; источники и индекс hook не переписывает.

Частично staged исходники/настройки и незарегистрированные новые C++ файлы
в собственной области нужно целиком добавить в индекс или отложить перед запуском.
Аналогично проверяются изменения самих hooks и скриптов проверки: тесты читают
рабочие файлы, поэтому они должны соответствовать индексу. Проверка не создаёт stash.
Изменения только Python/hooks запускают Python-тесты. Для документации C++ сборка
не нужна. План для текущего индекса: `python scripts/pre_commit.py --plan`;
полный запуск без commit: `git hook run pre-commit`.

Стандартная область исключает extlibs/ext, а также скопированные stb и
сгенерированные glad/Khronos в `core/src/Graphics/internal` и
`core/include/robot2D/Graphics/internal`. Для их ручной проверки нужен явный `-Scope`
на конкретную область. Заголовки зависимостей продолжают разбираться компилятором:
ошибки парсера не подавляются. Hook не добавляет анализ зависимостей автоматически.

Для передачи списка файлов между Python и PowerShell используется `-FilesFrom`
с JSON-массивом путей (его нельзя совмещать с `-Files`). Для ручного вызова из
PowerShell можно передать обычный массив `-Files @('file1.cpp', 'file2.cpp')`.

Форматирование изменённых файлов — отдельное явное действие разработчика:
hook сообщает расхождения и ничего не исправляет. Существующий файл при изменении
должен целиком соответствовать `uncrustify.cfg`; остальное дерево автоматически
не форматируется. Для предпросмотра и применения используются команды выше.

После добавления областей проверен выбор 164 единиц собственного кода без extlibs,
и отдельно 16 единиц robot2D-imgui без остальных библиотек и кода редактора.
Позже добавлены постоянные тесты editor/tests и включены в стандартную область;
точное число единиц меняется вместе с кодом и опциями сборки.

## Проверки этого шага

Постоянный набор регрессий и команды запуска после TEST-01 описаны в
[тестах редактора](editor-testing.md). Временные smoke-тесты ниже — история
первоначальной настройки диагностики, а не основной способ проверки проекта.

- Редактор собран командой `cmake --build cmake-build-debug --target robot2D -j 4`.
- Smoke-test реального Logger и ConsoleLog проверил уровни INFO/ERROR и новый
  формат с датой, миллисекундами и ID потока.
- Uncrustify проверен на отдельном примере с if, доступом через указатель,
  lambda с trailing return type, строкой и комментарием; исходники не форматировались.
- Полная интерактивная проверка запуска и завершения редактора не выполнялась.
- Сборка показывает существующее предупреждение `EntityManager::getContainer()`:
  управление может достичь конца функции, возвращающей ссылку. Оно не исправлялось
  в задаче настройки диагностики.

Официальные справочники: [clang-tidy](https://clang.llvm.org/extra/clang-tidy/),
[Uncrustify](https://github.com/uncrustify/uncrustify).
