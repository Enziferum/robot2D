# Версии robot2D

Политика согласована 2026-10-15 в VERSION-01. Движок и редактор имеют общую
версию. Последний опубликованный старый релиз — v0.7; текущая разработка —
0.8.0-dev, будущий стабильный релиз — v0.8.0. Новая версия сама по себе не
означает, что все задачи roadmap уже выполнены или релиз опубликован.

## Единый источник

Числа меняются только в корневом `CMakeLists.txt`:

```cmake
project(robot2D VERSION 0.8.0)
```

`cmake/Version.cmake` добавляет канал и сведения Git, затем генерирует
`<build>/generated/include/robot2D/Version.hpp`. Его публичные определения:

| Определение | Назначение |
|---|---|
| RB2_MAJOR_VERSION / RB2_MINOR_VERSION / RB2_PATCH_VERSION | Числовые компоненты |
| RB2_VERSION_PRERELEASE | dev, rc.1 либо пустая строка |
| RB2_VERSION | Например 0.8.0-dev или 0.8.0 |
| RB2_VERSION_FULL | Например 0.8.0-dev+g0123456789ab |
| RB2_GIT_SHA | Полный SHA HEAD, либо unknown без Git |
| RB2_BUILD_ID | По умолчанию первые 12 символов SHA, либо local |

`Config.hpp` сохраняет доступ к прежним major/minor макросам и подключает
сгенерированный заголовок. Версия в логах движка, окне/браузере проектов,
конфигурации редактора и метаданных новых проектов/кэша берётся из него.
Отдельных литералов 0.7/0.5 для текущей версии больше нет.

По умолчанию `RB2D_VERSION_PRERELEASE=dev`. Стабильная и кандидатная сборки:

```text
cmake -S . -B <release-build> -DRB2D_VERSION_PRERELEASE=
cmake -S . -B <rc-build> -DRB2D_VERSION_PRERELEASE=rc.1
```

Использовать выделенные build-каталоги с зависимостями согласно инструкции
по сборке. Пустой канал даёт 0.8.0 без dev/SHA в строке версии; полный SHA
остаётся доступным отдельно. Канал — непустые компоненты из букв, цифр и '-'
через точки; чисто числовой компонент не может иметь ведущих нулей.

SHA читается из текущего checkout, включая detached HEAD и Git worktrees.
CMake следит за HEAD и ссылкой ветки: следующий build после commit/checkout
обновляет заголовок. Это SHA коммита, а не хеш незакоммиченных правок; dirty
состояние строкой версии не удостоверяется. Время сборки и счётчик запусков
не добавляются. Без Git или в исходном архиве будет 0.8.0-dev+local и SHA unknown.
Архив, распакованный внутри другого репозитория, не заимствует его SHA.

Прежний параметр `RB2D_EDITOR_BUILD_ID` сохранён для пользовательской метки
сборки: например `-DRB2D_EDITOR_BUILD_ID=ci.123`. Он изменяет RB2_BUILD_ID,
но не подменяет фактический Git SHA и метаданные SHA в dev-версии.
Допустимы буквы, цифры, '.', '_', '+' и '-'.

## Повышение версии и релизы

- До 1.0 patch предназначен для совместимых исправлений. Minor — завершённый
  этап развития; несовместимые изменения допускаются с явным описанием перехода.
- После 1.0 major обозначает несовместимые изменения публичного контракта,
  minor — совместимые возможности, patch — совместимые исправления.
- Версию повышаем отдельным осмысленным изменением с ID задачи. Каждый commit
  уже различается по SHA; автоматического повышения от количества коммитов нет.
- Теги: `v0.8.0`, кандидаты — `v0.8.0-rc.1`. Старые теги не перемещаем и не
  переименовываем. Новое исправление опубликованного релиза получает новый patch.
- Перед релизом согласовать состав, обновить описание изменений/совместимости,
  собрать точный commit с соответствующим каналом и проверить Windows/Linux CI,
  а также необходимые ручные сценарии редактора. После проверки отдельно создать
  тег и GitHub Release. VERSION-01 не публикует релиз автоматически.
- Версия приложения не является гарантией неизменного C++ ABI. Контракты API
  и необходимость пересборки зависимого кода описываются в релизе.

## Версии файлов

Версия приложения и версия структуры данных — разные величины. Поля
`Editor Version` в проекте и `EditorVersion`/`EditorBuild` в кэше — сведения
о редакторе. Загрузчик не должен отклонять файл только из-за их отличия.
Загруженное старое значение Editor Version сохраняется; новая версия записывается
при создании нового проекта.

`CacheVersion` управляет схемой кэша и её миграциями независимо от 0.8.0.
В VERSION-01 схема кэша остаётся 1, форматы проектов, сцен и prefab не меняются.
При будущем изменении схемы нужны отдельная версия формата, проверка старых
и неизвестных новых файлов и продуманный путь миграции/отказа без потери данных.
Само повышение версии приложения миграцию не запускает.

## Проверка

`python -m unittest discover -s scripts/tests -v` включает реальные минимальные
CMake/Git fixtures для версий без зависимостей движка. Нужны CMake, Ninja и Git.
Они проверяют release/dev/rc, отсутствие Git, неверные параметры, worktree,
detached HEAD и обновление SHA через build без ручного reconfigure.

Headless CTest `editor-version` проверяет согласованность окна/конфигурации,
версии нового проекта и кэша, а также загрузку проекта с Editor Version 0.5
при прежней схеме кэша. Он входит в robot2D-editor-test-suite и CI.
