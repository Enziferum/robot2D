# SAVE-01 и LOG-01: проверка 2026-10-15

Работа выполняется в изолированной ветке codex/log-01-save-diagnostics поверх
проверенной VERSION-01 (PR #62). Параллельные изменения RENDER не включены.
Пользователь сообщил, что уже выполнял ручные сценарии и отдельно пришлёт
результаты; до получения результатов галочки настоящего UI не закрываются.

## Подтверждено автоматически

Актуальный robot2D и robot2D-editor-test-suite собраны Ninja/Release, GCC 16.2.0.
CTest: 45/45 без пропусков, включая 9 graphics/integration на реальном скрытом
OpenGL 4.5 контексте. Это запуск модели/маршрутизации, а не управление настоящими
ImGui popup и drag/drop мышью.

| Область | Фактическая проверка |
|---|---|
| Save / Save As | Успех сбрасывает dirty; ошибка записи сохраняет путь, dirty и исходный файл |
| Отказ до сериализации | Нет сцены / недоступен script interactor: false, SceneSerialize, путь и причина в ERROR; файл не создаётся/не меняется |
| Повтор после отказа | Успешный Save As сбрасывает ошибку SceneManager |
| Повреждённые данные | NaN не перезаписывает существующий валидный файл |
| Закрытие проекта | Ошибка Save не вызывает callback закрытия; успешный Save и Discard проходят соответствующие ветки |
| Загрузка | Последний запрос применяется; повреждённый/отсутствующий файл и недоступный interactor не заменяют старую сцену |
| Первый неудачный Load | Состояние LoadFailed, ошибочная сцена не публикуется |
| Drag/drop payload | Постоянный headless-сценарий проверяет распаковку и маршрут OpenSceneMessage |

В SceneManager::save исправлены два молчаливых ранних отказа: отсутствующая сцена
и недоступный script interactor. Они теперь устанавливают SceneSerialize и пишут
`[SceneSave] Rejected; path='...'; reason=...`. Проверка добавлена в существующий
graphics-сценарий editor-scene-save-dirty; сообщения проверяются в реальном файле
logger, а не подменённым sink. При обычной ошибке записи остаются Started → Failed
с путём, категорией ошибки и подробностями; при успехе — Started → Completed.

Команды для выделенной сборки:

```text
cmake -S . -B <build-dir> -DRB2D_EDITOR_GRAPHICS_TESTS=ON
cmake --build <build-dir> --parallel 4 --target robot2D robot2D-core-tests robot2D-editor-test-suite
ctest --test-dir <build-dir> -C Release --no-tests=error --output-on-failure --timeout 60
```

Каталог должен быть уже подготовлен с Release, включёнными core/editor-тестами
и зависимостями редактора. Graphics требуют доступного OpenGL; код 77/Skipped
не является успешным подтверждением. Локальный pre-commit по-прежнему запускает
только headless; graphics проверяются отдельно и в Linux CI.

## Результаты настоящего UI: ожидаются от пользователя

1. Повторный drag/drop сцены → изменение объекта → Save → повторное открытие:
   данные на месте, dirty сброшен, открыта выбранная сцена.
2. Несколько переходов A → B → A с сохранением: нет потери изменений/перепутанных сцен.
3. Невозможная запись: popup остаётся открыт, проект и рабочие данные остаются;
   после устранения причины Save можно повторить.
4. Cancel/escape: сцена, выделение и dirty сохраняются; смена/закрытие не выполняется.
5. В логах реального запуска → открытия → ошибки → завершения понятна цепочка:
   путь/причина ошибки, завершение очереди до Mono, нет обычного INFO на каждом кадре.

По каждому пункту достаточно результата «прошло» или описания отклонения и действия,
на котором оно возникло. Для разбора логов сохранить robot2D.log **до следующего
запуска**: текущий basic_file_sink перезаписывает журнал при старте.

Ротация логов, аварийный cleanup setup, CancellationToken и архитектурное разделение
не добавлялись в этот шаг. События рендера остаются в параллельной RENDER-работе.
Без ручных результатов SAVE-01/LOG-01 остаются на проверке; автоматические тесты
не подменяют подтверждение настоящего UI.
